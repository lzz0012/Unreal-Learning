虚幻引擎所有对象的基类是UObject
## ue为什么需要c++反射机制
原生c++本身不支持反射机制，代码在编译后，类名，属性名，函数名等元数据会消失，而虚幻引擎作为游戏引擎，需要在运行时动态地检查并操作这些信息，因此需要搭建属于自己的一套反射机制。UE 反射的本质，是为 C++ 类型额外构建一套运行时可查询的类型元信息，使引擎能够在运行时获取类、属性和函数的信息，并在此基础上支持编辑器、蓝图、序列化、GC、网络复制等系统。

## UPROPERTY
### 详细面板说明符
- EditDefaultsOnly
  - 蓝图类可编辑
- EditInstanceOnly
  - 蓝图实例可编辑
- EditAnywhere
- VisibleDefaultsOnly
  - 蓝图类可见不可编辑
- VisibleInstanceOnly
  - 蓝图实例可见不可编辑
- VisibleAnywhere

### 事件图说明符
- BluePrintReadOnly
  - 事件图中可获取，不能修改
- BluePrintReadWrite
  - 事件图即可以Get又可以Set

### 类别说明符
- Category
  - 将变量归类

### 元指定符
- meta
  - AllowPrivateAccess
    - meta = (AllowPrivateAccess = "true")将私有变量暴露给子类蓝图事件图

## UFUNCTION
### 说明符
- BluePrintCallable
  - c++函数暴露给蓝图中可调用
- BlueprintPure
  - 暴露给蓝图纯函数，没有输入和输出引脚

## UCLASS
标记UObject子类，以便UObject处理系统识别。

## UObject提供的功能
- 垃圾回收
- 引用更新
- 反射
- 序列化
- 默认属性变化自动更新
- 自动属性初始化
- 自动编辑器整合
- 运行时类型信息可用
- 网络复制

## 虚幻头文件工具
为利用 UObject 派生类型所提供的功能，需要在头文件上为这些类型执行一个预处理步骤，以核对需要的信息。 该预处理步骤由 UnrealHeaderTool（简称 UHT）执行。UObject 派生的类型需要遵守特定的结构

## 头文件格式参考
```c++
#pragma once

	#include 'Object.h'
	#include 'MyObject.generated.h'
	
	UCLASS()
	class MYPROJECT_API UMyObject : public UObject
	{
		GENERATED_BODY()

	};
```

### include　"MyObject.generated.h"
此行预计为此文件中最后一个 #include 指令。如此头文件需要了解其他类，可将它们在文件中的任意位置提前声明，或包括在 MyObject.generated.h 上。

### UCLASS()
UCLASS 宏使虚幻引擎能识别 UMyObject

### GENERATED_BODY()
GENERATED_BODY 宏不获取参数，但会对类进行设置，以支持引擎要求的基础结构。所有 UCLASS 和 USTRUCT 均有此要求。

### class MYPROJECT_API UMyObject : public UObject
如果MyProject 希望将 UMyObject 类公开到其他模块，则需要指定 MYPROJECT_API
